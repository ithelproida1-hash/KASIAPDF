# MASTER PROMPT — INTERNAL COMPANY PDF PLATFORM

You are the senior software architect and implementation engineer for this project.

We are building a private, company-internal PDF platform inspired by iLovePDF, but we will NOT copy iLovePDF's branding, proprietary UI, code, or assets.

The project will use:

- Frontend: Next.js + React + TypeScript
- UI: Tailwind CSS + shadcn/ui
- Deployment: Vercel
- PDF processing: Stirling-PDF
- Local PDF processing server: Windows 11
- Stirling-PDF: self-hosted on the Windows 11 machine
- Connection from Vercel to Windows: secure tunnel such as Cloudflare Tunnel
- Database: Supabase PostgreSQL if persistent application data is required
- File storage: Prefer local temporary processing on Windows; optionally Cloudflare R2/Supabase Storage for persistent files
- Development: Windows 11
- AI coding assistant: OpenCode + DeepSeek
- Package manager: pnpm
- Language: TypeScript
- Framework: Next.js App Router

REFERENCE PROJECT:

Stirling-PDF:
https://github.com/Stirling-Tools/Stirling-PDF

IMPORTANT:
Do not fork and unnecessarily rewrite Stirling-PDF.

Use Stirling-PDF as the PDF processing engine and integrate with its REST API.

Stirling-PDF already provides PDF operations, REST APIs, OCR, conversion, compression, signing, redaction, workflows and many other tools.

The goal is to create a separate, clean company frontend/application that communicates with Stirling-PDF.

--------------------------------------------------

  |
  v

  |
  v

MAX_FILE_SIZE
MAX_FILES
MAX_TOTAL_UPLOAD_SIZE

Do not hardcode these limits.

--------------------------------------------------
10. TEMPORARY FILE HANDLING
--------------------------------------------------

PDFs may contain confidential company information.

Temporary files must be cleaned up.

Requirements:

- never leave uploaded files indefinitely
- delete temporary files after successful processing
- delete temporary files after failed processing
- use unique job IDs
- never use predictable filenames
- prevent path traversal
- validate file extensions
- validate MIME types
- validate actual PDF signatures where applicable

Do not log PDF contents.

Do not log sensitive filenames unnecessarily.
